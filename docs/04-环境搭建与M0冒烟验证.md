## 2. 安装脚本用法：`scripts/setup_windows.ps1`

### 2.1 运行方式
以**管理员身份**打开 PowerShell（右键 → 以管理员身份运行），执行：

```powershell
# 进入脚本所在目录后
powershell -ExecutionPolicy Bypass -File .\setup_windows.ps1
```

> ⚠️ **UAC 弹窗**：安装 Visual Studio 时会弹出 UAC 授权，需客户手动点「是」。
> ⚠️ **非管理员会失败**：脚本预检若发现非管理员且未跳过 VS，会提示退出；请勿在非管理员会话强行运行。

### 2.2 常用参数

| 参数 | 说明 |
|---|---|
| `-InstallRoot` | 工具链根目录，默认 `C:\dev`。**请勿用含空格或中文的路径**（如 `C:\Program Files`），Flutter / Gradle 支持差。 |
| `-FlutterVersion` | 锁定 Flutter 版本（如 `3.35.4`）；留空用 stable 当前版。 |
| `-AutoAcceptAndroidLicenses` | 自动接受 Android SDK 许可（等同逐条输入 y）。**使用该开关即表示客户已阅读并同意 Google 许可条款**；不加则需手动接受（见 2.4）。 |
| `-UseChinaMirror` | 启用国内镜像加速 Flutter / pub 下载（网络不畅时尝试）。 |
| `-SkipFlutter` / `-SkipVisualStudio` / `-SkipJdk` / `-SkipAndroid` / `-SkipGit` | 跳过对应组件（用于补装某一部分）。 |

示例（只补装 Android 并接受许可）：
```powershell
powershell -ExecutionPolicy Bypass -File .\setup_windows.ps1 -SkipFlutter -SkipVisualStudio -SkipJdk -AutoAcceptAndroidLicenses
```

### 2.3 幂等性
脚本可重复执行：已安装的组件自动跳过，仅补齐缺失部分。

### 2.4 需客户手动完成的两处
1. **VS 的 UAC**：安装 VS C++ 工作负载时弹窗，点「是」。
2. **Android SDK 许可协议**：若未加 `-AutoAcceptAndroidLicenses`，脚本结束后需新开终端手动接受：
   ```powershell
   flutter doctor --android-licenses   # 逐条输入 y（通常 5–7 条）
   ```

### 2.5 安装后衔接
脚本末尾会提示：**关闭所有终端、重新打开 PowerShell**（环境变量只对新建进程生效），然后运行验证脚本（§3）。

## 3. 验证脚本用法：`scripts/verify_env.ps1`

### 3.1 运行方式（重新开终端后）
```powershell
powershell -ExecutionPolicy Bypass -File .\verify_env.ps1
```

脚本将：
1. 直接探测基础工具链（Flutter / Dart / Git / Java / JDK / adb / JAVA_HOME / ANDROID_HOME / VS C++ / Windows SDK / 磁盘）；
2. 执行 `flutter doctor -v` 并解析输出；
3. 明确给出**两个结论**：
   - **A) 本机能否构建 Windows 桌面产物**（`flutter build windows`）
   - **B) 本机能否构建 Android 产物**（`flutter build apk --debug`）
4. 在 `scripts/` 下生成报告文件 `env_report_<时间戳>.txt`。

### 3.2 退出码含义

| 退出码 | 含义 |
|---|---|
| 0 | Windows 与 Android 均可构建 |
| 10 | 仅 Windows 可构建 |
| 20 | 仅 Android 可构建 |
| 30 | 两者均不可构建 |
| 40 | 未找到 Flutter SDK |

### 3.3 客户回传
请将生成的 `env_report_<时间戳>.txt` **回传我方**。我方据此确认是否可进入 M0 冒烟。若结论为"不可以"，按报告列出的原因逐条补齐后重跑本脚本（多数情况重跑 `setup_windows.ps1` 即可自动补齐）。

> macOS / iOS 产物：本期不涉及，Windows 机器物理不可构建，报告会明确标注"本期不涉及"。

## 4. M0 冒烟验证步骤（空白工程）

> 前置：§3 验证结论为"Windows 与 Android 均可构建"。M0 **不写任何业务代码**，仅验证构建链路打通。

### 步骤 1 —— 建立空白 Flutter 工程
```powershell
flutter create --org sudututor.app --platforms=windows,android sudoku_tutor
cd sudoku_tutor
```
- `--org sudututor.app`：应用 ID 前缀，对齐客户锁定的包名 / Bundle ID `sudututor.app`。
- 本期 M0 冒烟阶段应用 ID 暂为 `sudututor.app.sudoku_tutor`；**正式交付前**在 `android/app/build.gradle.kts` 的 `applicationId` 与 iOS `PRODUCT_BUNDLE_IDENTIFIER` 统一改为精确值 `sudututor.app`（客户已锁定，后期改包名代价极高，故提前定死）。

### 步骤 2 —— 构建 Windows 产物
```powershell
flutter build windows
```
- 产出目录：`build\windows\x64\runner\Release\`（含 `sudoku_tutor.exe` + 一系列 `.dll` 及依赖）。
- **本期策略**：客户冒烟直接用此目录即可，**安装器（MSIX / InnoSetup 等）后续另做**，不在 M0 范围。

### 步骤 3 —— 构建 Android apk（debug 签名）
```powershell
flutter build apk --debug
```
- 产出：`build\app\outputs\flutter-apk\app-debug.apk`（**debug 签名**，能装能跑，不能上架）。
- 安装到 Android 设备：`adb install build\app\outputs\flutter-apk\app-debug.apk`（需开发者选项 / USB 调试已开）。

### 步骤 4 —— 交付客户冒烟
将以下两样交给客户：
1. Windows：`build\windows\x64\runner\Release\` 整个目录（双击 `sudoku_tutor.exe` 验证启动）。
2. Android：`app-debug.apk`（安装验证启动与基本交互）。

> M0 通过标准（客户主观冒烟）：两个平台均能成功启动空白 App、无崩溃、无缺失依赖弹窗。M0 不验证任何业务逻辑。

## 5. 离线出题工具（Dart CLI）骨架计划

> 本计划描述**工具形态与复用关系**，非实现代码（不写应用业务代码）。该工具在 **M1 算法层就绪后**开发，不阻塞 M0。

### 5.1 目标
批量生成 / 扫描数独盘面，按"**启用规则集**"筛选**含有目标技巧**的题目，导出为 JSON 打包进 App 的 `assets`，实现"完全离线 + 教学关含目标技巧"的供给（对应客户拍板：不实时采样生成，题目打包内置）。

### 5.2 与 App 的关系（关键）
- **复用同一套 Dart 引擎**：推理规则函数（唯一余数、裸对/隐对、区块排除、Fish、XY/XYZ/W-Wing、UR、涂色、AIC 等）是 App 算法层的纯 Dart 实现，**CLI 工具直接 import 同一 engine 包**，不另写一份。
- 求解器 / 候选数模型 / 难度分级器同样复用，保证"工具筛出的题"与"App 内求解判定"口径一致。

### 5.3 流程（骨架）
1. **生成 / 载入盘面**：随机生成满盘并挖洞（回溯保证唯一解），或载入外部盘面。
2. **标注**：用启用规则集的求解器逐步求解，记录每一步用到的技巧及其涉及格、删数、可视化标记。
3. **筛选**：按目标技巧标签（如"恰好需要 Swordfish""盘面含 XY-Wing 且前置步骤在已学范围"）过滤，命中才保留。
4. **导出 JSON**：每题一个结构化对象（题面、提示格掩码、解题脚本、技巧标签、可视化数据），写入 `assets/puzzles/`。
5. **打包**：构建时随 `pubspec.yaml` 的 `assets` 声明内置进 App。

### 5.4 关键设计点（非代码）
- **规则集开关**：以配置声明的"启用规则集"驱动筛选，直接对应 §6 的 scope 档位（T1/T2/T3）——开关即客户选定档位。
- **输出结构对齐教学关 JSON 格式**（doc 00 第三部分：JSON 资源 + CI 回放校验），CLI 产出可直接被 App 消费，并能被 CI 用引擎回放校验可解性。
- **命中率现实**：高级技巧严格必需命中率极低（Swordfish 0.1%–1%、特定 AIC <0.1%，见 doc 02 §3.2）；CLI 在桌面端离线跑、可长时间批处理，规避了"运行时实时生成不可行"的红线（doc 00 L-05）。
