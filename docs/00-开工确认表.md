### L-01　这台机器现在什么都构建不了 ⚠️ 最紧急
实测结论（真跑了命令，不是猜的）：

| 依赖 | 状态 |
|---|---|
| Flutter SDK / Dart SDK | ❌ 完全没有，9 处常见路径全空 |
| Visual Studio + C++ 工具链 | ❌ 目录不存在（**Windows exe 必需**） |
| Windows SDK / MSVC / Ninja | ❌ 全无 |
| JDK | ❌ 只有 PDF24 和考试客户端自带的私有 JRE，无 javac，不可用 |
| Android SDK / Gradle / adb | ❌ 环境变量为空，目录不存在 |
| Git 2.54 / CMake 4.3.3 / Node / Python | ✅ 有 |

- **Windows exe：现在交不了**，补齐工具链后可以
- **Android apk：现在交不了**，补齐后可以
- 连 `flutter test` 都跑不起来，**连"源码 + 单元测试"这个最低交付都受阻**
- 需要下载安装约 **20–28 GB**，耗时 1–4 小时。C 盘剩 136 GB，够但不宽裕

**关键**：本会话没有系统级安装权限（实测中 `vswhere.exe` 被安全策略直接拦截）。Visual Studio 要管理员 + UAC 弹窗，Android SDK 要交互式接受许可协议——**必须你或你的 IT 手动装，或者书面授权我们在非沙箱、管理员权限下跑安装脚本**。

> **需要你决定**：(a) 你自己/IT 装，我们提供逐步脚本和验收命令；(b) 授权我们在管理员权限下装；(c) 换一台已有 Flutter 环境的机器。

### L-02　macOS / iOS 的打包产物，在 Windows 上永远做不出来
这不是工期问题，是苹果的硬性平台限制：编译 iOS/macOS 必须用 Xcode，Xcode 只跑在 macOS 上。iOS 真机分发还要 Apple Developer 账号（99 USD/年）+ 签名证书，公司主体申请要 **2–6 周**。

> **推荐**：本期把 macOS/iOS **移出交付范围**，只交付"已做好多端适配的源代码 + 构建说明"。等你有 Mac 环境了，作为独立变更单追加。
> **如果你坚持要**：需要提供 Mac 硬件（或授权的 Mac 云构建服务）+ Apple 开发者账号，且账号申请**这周就得启动**。

### L-03　Android Release 签名密钥必须你提供
`flutter build apk` 默认是 debug 签名，**不能上架任何应用商店**。正式分发需要你提供 release keystore + 密码/别名。

⚠️ 必须让你知道：**keystore 一旦丢失，这个 App 永久无法发布更新**——这是 Android 生态不可逆的约束，没有任何补救办法。

> **推荐**：本期按 debug 签名交付（能装能跑，不能上架），规避密钥托管的法律和安全责任。需要上架时你自己生成并保管 keystore。

### L-04　"强制校验玩家必须用了目标技巧" —— 严格意义上做不到
这条要说清楚：系统只能看到操作事件流，**看不到玩家脑子里的推理**。一个真的用 X-Wing 推出来的玩家、一个背过答案的玩家、一个随手蒙对的玩家，**可以产生完全一样的操作序列**。这是信息论层面的不可判定，砸多少人力都解决不了。

必须降级成四层近似判定：
1. 关键删数校验（盘面到达触发态后，必须先正确删完目标候选数）
2. 前置条件锁（没获得逻辑依据前锁死填数——**打击猜数最有效的一层**）
3. **模式指认交互**：要求玩家先点选构成技巧的关键格，再执行删数。把"不可观测的心理行为"转成"可观测的 UI 行为"，是唯一真正有效的手段。**强烈推荐，但要你拍板**（+3–5 人日）
4. 试错惩罚

> **需要你决定**：第 3 层（模式指认）做不做？做了教学效果质变，但玩家操作步骤变多。

### L-05　"实时生成一道必须用某高级技巧才能解开的题" —— 不可行
实测量级（拒绝采样命中率）：

| 目标 | 命中率 | 期望耗时（桌面端） |
|---|---|---|
| Swordfish 严格必需 | 0.1%–1% | 30 秒 – 5 分钟 |
| UR 必需 | <0.5% | 1 – 10 分钟 |
| 特定 AIC 必需 | <0.1% | 5 分钟 – 1 小时 |

移动端再乘 3–5 倍。更致命的是：教学关卡还要求技巧出现在**合适的教学时机、图形形态清晰、前置步骤在已学范围内**——这是课程设计约束，随机生成 + 过滤彻底失效。

> **必须改为离线预置题库**。附带一个需求书里没列的新交付物：**离线出题工具（Dart CLI，2–3 人日）**，用于批量筛题、标注技巧标签。

### L-06　"每日一题 + 排行榜"（P2）和"完全离线"（P0）直接打架
排行榜要服务端 + 网络权限 + 用户体系，而需求书 §2.5 和 §4 两处白纸黑字要求"完全离线"。

> **推荐**：P2 排行榜明确移出本期。想保留"每日一题"的话，降级为**按日期种子从本地题库确定性选题**（无排行榜、无联网）——零成本，建议采纳。

### L-07　品牌与法务资产你一个字没提，但有一项后期改不动
需求书通篇没提：应用包名 / Bundle ID、应用名称、图标、启动图、CJK 字体商用授权、隐私政策 URL。

⚠️ 其中 **包名（如 `com.yourcompany.sudokututor`）是唯一后期改动代价极高的项**——改包名 = 发布一个全新应用，老用户无法覆盖升级、存档全丢。而且 `com.example.*` 会被 Google Play 直接拒收。**现在就得定。**

> **需要你给**：包名、应用中文名/英文名。图标和字体我们可以先用开源方案顶上。

### L-08　没有验收标准 = 无限期返工（最大的商业风险）
需求书第六章只列了交付物清单，**没有任何一条可度量的"完成"定义**。

> **推荐验收口径**：
> - 交付物齐全
> - 核心算法层单测全通过，行覆盖率 **≥85%**，技巧识别器关键路径分支覆盖 100%
> - 技巧识别"准确率"重定义为：**精确率必须 100%**（误删候选数会把谜题变成死局，零容忍）+ **召回率 ≥95%**
> - 按双方共同确认的《验收用例表》（预计 80–120 条）逐条走查，阻断/严重缺陷 100% 修复，一般缺陷 ≤5 个可转维护期
> - 验收期 10 个工作日，逾期未提异议视为通过
>
> 开工前额外花 1–2 人日一起写《验收用例表》，是整个项目性价比最高的一笔投入。

## 第三部分 · ⚪ 我方自决（不反对即通过）

| 项 | 决定 | 理由 |
|---|---|---|
| 状态管理 | **Riverpod**（不用 Provider） | 不依赖 BuildContext，算法层与业务层可脱离 Widget 树单测 |
| 本地存储 | **不用数据库。纯 JSON + path_provider** | ① 数据量只有几十 KB～个位数 MB，上 DB 是过度设计 ② **Isar 维护活跃度存疑，且桌面端默认运行时联网下载 isar.dll，与"完全离线"直接冲突** ③ sqflite 桌面端要额外分发 sqlite3.dll。**此项偏离需求书 §3 原文，需你点头** |
| 关卡数据格式 | **JSON 资源文件** + CI 回放校验 | 遍历所有关卡 JSON 用引擎回放解题脚本，算法一改动破坏可解性就立即报警。性价比极高 |
| Web 端 | **本期不做** | Flutter 3.29 起已移除 HTML renderer，"包体小"的退路没了，必然引入 1.5–2 MB wasm/js |
| 存档迁移 | 从第一版就带 `schemaVersion` + 迁移链 | 不做的话，将来版本一升级用户存档就全丢 |
